# BPI-R4 / 25.12 EIP197 启动回归复核

## 基线与结论边界

- 用户确认可启动的源码：`4bb7cb7b`。
- 故障发布包的 manifest / 构建日志确认源码为 `fe2ff0d1`。
- 后者新增原生 EIP197 自动加载链。它由 `S10boot` 的 kmodloader 加载，早于 `S20network`；在此阶段卡死或崩溃，会使 DHCP、SSH 和 LuCI 都不可用。
- 两版之间没有修改 BPI-R4 的 U-Boot、设备树、SD 镜像生成定义或默认 LAN 端口定义。已发布 SD / FIT 的内核、设备树和 rootfs 内容校验通过。

以下是从代码中确认的缺陷及修补，**不等于已经通过故障设备的启动验收**。没有故障串口或实际启动结果，不能把某一处认定为此次故障的唯一根因，也不能仅凭指示灯确认内核尚未加载。

## 启动与资源管理

| 路径 | 确认的问题 | 修补 |
| --- | --- | --- |
| DDK Kbuild | 不同模块用不同配置编译，却共用同一对象输出路径 | 前一轮已隔离模块对象，避免配置互相覆盖 |
| OF / LKM 探测 | 获取资源前即发布设备指针，probe 失败仍可能被上层当作成功 | 完整取得映射、可选时钟、全部 IRQ 后才发布设备；保留错误码并撤销资源 |
| 时钟 | 忽略时钟获取、使能失败，包括 `-EPROBE_DEFER` | 缺省时钟允许为空，真实错误向上传递；内联驱动退出时恢复原强制时钟寄存器值 |
| 控制模块 | 忽略 packet / classification / DRBG 初始化结果；布尔返回值误返正错误码 | 逐阶段检查，失败只撤销已完成的阶段；缺失必要固件时停止后续初始化 |
| IRQ | 用系统 IRQ 编号直接索引固定 256 项数组 | 按控制器表匹配实际 IRQ；覆盖大于 255 的编号 |
| IRQ 失败退出 | 部分 IRQ 已注册后直接返回，可能遗留已卸载模块的处理函数 | 撤销已注册 IRQ，结束 tasklet 后再释放相关资源 |
| UMDevXS / SHDevXS | 部分失败分支漏清理或清理未初始化资源 | 记录已完成的阶段，成对释放设备、字符设备、缓冲管理和锁 |
| DMA | 从对齐后的内部地址映射整个原始分配长度；映射失败释放内部地址 | 只映射可用长度，按相同长度解除映射；释放原分配地址 |
| DMA 地址 | 用 `__pa()` 代替 DMA API 的总线地址 | 从 DDK DMA 资源取得总线地址写入 CDRT；保留原始 coherent 分配地址用于释放 |
| PCE | 关闭本地中断后无限轮询硬件完成位 | 最多等待 10 ms，失败返回错误并停止后续事务 |
| PCE 查表 / 清理 | 失败时带锁返回；初始化错误未向上传递 | 每条路径解锁并传播错误；probe 未完成时模块加载失败，阻止依赖模块访问无效资源 |
| 驱动初始化 | 映射 / hook 失败后仍发布回调，或资源生命周期绑定到错误模块 | 初始化成功后才发布回调；复用 DDK 映射；对称撤销临时映射、工作队列和 affinity hint |

PCE 的无限等待和查表锁问题在基线中也存在，是本次依赖链审查发现的旧缺陷；不能把它们直接当成两版之间的新增回归。IRQ 越界是否在故障设备上实际发生，仍需其真实 IRQ 分配记录。

## XFRM / HNAT 数据路径

- `xdo_dev_offload_ok()` 只判断能否卸载，不发送、释放或分片数据包。
- 新增可选的 `xdo_dev_packet_xmit()`，明确每条返回路径均接管数据包；内核调用后不再读取或释放同一数据包。其他驱动保留标准发送路径。
- 在修改以太网头之前扩展 headroom；分片、GSO 分段、校验和错误都遵循相同的所有权约定。
- ARP / ND 未解析时只触发邻居请求，不向 WAN 发送未经加密的数据包副本。
- 删除仅凭“策略已卸载”就放行入站包的旁路，使用 RX secpath 进行正常策略验证。
- 状态删除、策略删除和重建使用引用计数保留上下文及 CDRT 索引，清除流项时不引用已释放的 SA 上下文；移除未使用的递归自旋锁清理函数。
- 只在支持的 MTK 以太网设备或单端口 WAN bridge 上安装本驱动的操作，保护 RTNL 遍历和其他驱动的操作表。
- HNAT 从 RCU 保护的局部指针调用 EIP 提供者，并检查实际 SA；软件 XFRM 流不再一律被标为可硬件卸载。
- debugfs 文件持有模块引用，并明确字节/包数是主机观察值，不能当作硬件总计数。

当前实现拒绝 crypto-only offload、ESN、跨地址族内外层包，以及不支持的 VLAN / PPP / 多端口桥路径。隧道模式与传输模式仍须分别进行硬件收发验收。

这些接口修改需要整体重新构建固件及内核模块，不能把新模块单独复制到旧内核中使用。

## 包配置

修复 EIP 模式与派生模块之间的循环选择：组件按 `CRYPTO_OFFLOAD_INLINE` 默认选中；控制工具依赖已经选择的驱动和协议，不反向强制选择它们。完整私有配置解析后保留原有 EIP / NPU / L2TP / PPP 选项。普通版及私有版的 defconfig 文件均未改写。

## 已完成的验证

- Linux 6.12.112 原生补丁队列重放，核对生成源码与用于编译的源码一致。
- ARM64 XFRM 对象、HNAT、PCE 和五个 EIP 模块编译；`-Wall -Werror`、严格 modpost，未把缺失符号降级为警告。
- `CONFIG_XFRM_OFFLOAD` 关闭时的新接口预处理保护检查。
- 59 项主机故障注入检查：平台资源失败/重试、控制模块初始化回退、CDRT 查表锁、大 IRQ 编号；使用真实 C 函数体及模拟内核 API，启用 ASan / UBSan。
- 用当前包定义重新生成配置元数据，完整私有配置无循环依赖错误；四个固件文件与故障发布包中的内容一致。

主机故障注入不能验证 ARM64 DMA 一致性、真实中断或芯片寄存器行为。私有配置使用 inline 模式；上述结果没有把 lookaside / CAPWAP 或实机启动、双向硬件加速认定为已通过。
